# Среда разработки Асгарда

Фаза 3 добавила финансовые таблицы и поле точности валюты. Фактические проверки и границы защиты истории — application/PHASE3.md. Настройка настоящей авторизации отложена пользователем. Базы разработки и автоматических тестов по-прежнему раздельны; Beget не используется.

Фаза 1, начата 24 октября 2026 года по поручению пользователя. Это подготовка инструментов и проверок, не реализация входа или финансовых модулей.

Дополнение фазы 2: приложение находится в `application/`; запуск, результаты и оставшаяся приемка — `application/PHASE2.md`. Добавлены локальные базы `asgard_development` и `asgard_test` с разными учетными записями и скрипты Initialize/Start/Stop/Test-Application. Автоматические тесты очищают только `asgard_test`. GitHub workflow `application.yml` проверяет сборку и логику на MySQL; Pages по-прежнему публикует только лендинг. Настоящий вход у провайдеров не проверен.

## Где что работает

- Основные файлы и локальные инструменты: `F:\Проекты\Асгард`.
- Код и автоматические проверки: https://github.com/EnzoAmore-git/Asgard.
- GitHub Pages: только статический лендинг из `landing/dist`. Живой сервер PHP, MySQL и авторизация на Pages не работают.
- Работающий сервер будущего приложения: локальная среда. GitHub Actions создает временную MySQL для тестов и не является постоянным приложением для участников клуба.
- **Beget не трогать до готовности MVP.** В начале этой фазы просмотрена главная панель и открыта существующая сессия терминала. Команды в терминале не выполнялись, настройки/файлы/БД/сайты не менялись. После уточнения пользователя работа с Beget прекращена. Адрес тестового сайта и DNS сейчас не нужны.

Отдельный репозиторий для этого не нужен. Никакие новые платные сервисы не подключались.

## Подготовленные локальные инструменты

PHP 8.4.27 x64 NTS, Composer 2.10.3 и MySQL Community 8.4.13 размещены в игнорируемом `.local/`. Node.js 24.20.0, npm 11.19.0 и Git 2.55.0 уже доступны на компьютере. Пакеты скачаны с официальных сайтов, перед запуском проверены опубликованные контрольные суммы. MySQL проверен по опубликованной MD5 через HTTPS; это проверка целостности архива, не проверка подписи GPG. PHP и Composer проверены по SHA-256; установщик Composer — по SHA-384.

Системный PATH и службы Windows не изменяются, Docker/WSL не требуются. MySQL запускается только по требованию на `127.0.0.1:33084`, дополнительный X Protocol отключен. Случайные локальные пароли остаются в `.local/`, не выводятся в отчет и не отправляются на GitHub. Не использовать их как production-секреты.

Из-за работы MySQL с кириллицей в Windows при запуске создается временный путь `S:`, указывающий на основную папку Асгарда. Данные физически остаются на F:. Если S: уже занят, запуск прекращается без изменения существующего диска. Штатная остановка освобождает этот временный путь. При сбое сначала проверить локальный журнал и процесс, не удалять каталог данных для повторного запуска.

## Повторение подготовки

Команды PowerShell запускаются из основной папки проекта:

```powershell
./tools/environment/Install-LocalTools.ps1
./tools/environment/Install-LocalMySQL.ps1
./tools/environment/Start-LocalMySQL.ps1
./tools/environment/Test-LocalEnvironment.ps1
./tools/environment/Stop-LocalMySQL.ps1
```

Скрипты установки закрепляют версии. При изменении официальных метаданных или несовпадении контрольной суммы установка останавливается, проверка не отключается. Composer использует отдельные `.local/composer-home` и `.local/composer-cache`. Установленные PHP/Composer запускаются через явные пути или предоставленные скрипты; изменение глобального PHP не требуется.

Проверочная база — `asgard_environment`, не база будущего приложения. Диагностика создает только собственные таблицы со случайными именами и удаляет их после проверки. Скрипт отклоняет произвольное имя базы, чтобы случайно не запускать проверки против рабочих данных. В CI используется отдельная `asgard_ci`, уничтожаемая вместе с временным окружением.

## Что проверяется

`check.php`: только CLI, PHP 8.4, расширения Laravel и дополнительные intl/zip/sodium. Это не публичный диагностический endpoint.

`check-mysql.php`: MySQL именно ветки 8.4, InnoDB, создание внешних ключей, откат транзакции, фиксация и чтение кириллицы, отклонение дубля уникального значения и неверной ссылки. Это проверка возможностей среды, не проверка финансового журнала, гонок или бизнес-правил приложения.

`Test-LocalEnvironment.ps1`: обе проверки, Composer diagnose и синтаксис JavaScript существующего лендинга. Реальные уведомления, платежи и клубные данные не используются.

GitHub Actions: `.github/workflows/environment.yml`, Linux + PHP 8.4 + MySQL 8.4.13 + Node.js 24. Запускается на изменениях файлов среды в main и pull request, а также вручную. Использует только временные открытые значения паролей тестового контейнера, никаких секретов Beget. Права workflow — только чтение содержимого репозитория. Сборка React/Laravel и тесты приложения появятся в соответствующих следующих фазах, сейчас не объявляются выполненными.

## Результаты фазы

Локально пройдены: PHP и все требуемые расширения, синтаксис PHP и PowerShell, реальное подключение к MySQL 8.4.13, InnoDB/транзакции/ограничения/кириллица, Composer diagnose с ключами проверки и доступом к Packagist/GitHub, синтаксис JavaScript лендинга. Проверены запуск с существующими данными и штатная остановка MySQL. При доводке локального запуска исправлены кириллица в путях и отдельная служебная учетная запись с правом SHUTDOWN. В финале локальная MySQL остановлена, временный путь S: освобожден.

На GitHub успешно завершен [первый запуск Environment checks](https://github.com/EnzoAmore-git/Asgard/actions/runs/40050841796) для коммита `8c2f3ef`: контейнер MySQL 8.4.13, PHP runtime и синтаксис, реальные транзакции и ограничения, Node и синтаксис лендинга. Исправления скриптов локальной остановки проверены отдельно на Windows; Linux workflow не выдается за тест этих PowerShell-команд.

Не проверялись в этой фазе: приложение Laravel, вход Telegram/VK, интерфейс React, финансовые операции, конкурентные запросы, рабочий хостинг, нагрузка, восстановление. Сайт приложения по HTTPS и изоляция приватных файлов на рабочем хостинге отложены до готовности MVP по поручению пользователя.

Источники версий и ограничений: [PHP Windows](https://windows.php.net/download/), [Composer](https://getcomposer.org/download/), [MySQL 8.4](https://dev.mysql.com/downloads/mysql/8.4.html?os=3), [официальный образ MySQL](https://hub.docker.com/_/mysql), [требования Laravel 13](https://laravel.com/framework/docs/deployment). Проверены 24.10.2026.
