# Фаза 2 — вход и клубы

Реализованы серверный модуль Laravel и мобильные экраны React: Telegram/VK, явная привязка второго входа, несколько клубов, общие приглашения на 7 дней, участники, совмещаемые права, заморозка/исключение, передача владения и журнал изменений. Клуб создает оператор через доверенную команду, публичной регистрации клубов нет.

Финансы и тренировки еще не реализованы. Владение само по себе не дает финансовых полномочий. Право приема наличных отдельно от управления финансами. Все проверки доступа выполняются сервером. Секреты провайдеров и токены не передаются в интерфейс; внешние идентичности связываются только после подтвержденного входа.

## Локальный запуск на этом компьютере

Из `F:\Проекты\Асгард`, PowerShell:

```powershell
./tools/environment/Start-LocalMySQL.ps1
./tools/environment/Initialize-Application.ps1
Set-Location application
npm.cmd ci --ignore-scripts
npm.cmd run build
Set-Location ..
./tools/environment/Start-Application.ps1
```

Адрес: http://127.0.0.1:8000. Локальные инструменты уже установлены в `.local`; их установка описана в ENVIRONMENT.md. Для Windows с кириллицей MySQL использует отображение S:, физические файлы остаются на F:. Скрипты не устанавливают системные службы и не публикуют сервер в сеть.

Первый запуск создает `.env` с локальными ключами, не добавляемыми в Git. Повторная инициализация сохраняет настройки и применяет миграции без удаления данных. MySQL использует разные базы и учетные записи: `asgard_development` для просмотра, `asgard_test` исключительно для тестов. Тесты очищают только `asgard_test`; не подключать их к рабочим данным.

## Просмотр без приложений провайдеров

```powershell
Set-Location F:\Проекты\Асгард\application
../.local/php/php.exe artisan asgard:demo
../.local/php/php.exe artisan asgard:local-access 2
```

Команда demo печатает фактические идентификаторы вымышленных пользователей; подставить нужный вместо примера `2`. Она добавляет тестовый клуб, владельца и участника, не очищает существующие данные. Local-access печатает одноразовый адрес на 5 минут. Открыть его на этом компьютере. На экране есть отметка «Локальная проверка». Этот способ доступен только при APP_ENV=local, с адреса loopback и локальным именем хоста. В production он запрещен. Не публиковать локальные ссылки.

Для реального клуба оператор назначается доверенной командой `asgard:operator {user}`. Создание клуба: `asgard:club {name} --operator=ID --owner=ID --owner-name=ИМЯ --timezone=Europe/Moscow --currency=RUB --period-day=10`. Идентификаторы должны принадлежать уже созданным пользователям; настройки задаются оператором явно. Назначение владельца не дает ему финансовых прав.

## Что нужно сделать в Telegram и VK

Приложения пока не созданы пользователем. Поэтому настоящий вход, телефон и встроенные браузеры еще не проверены. Автоматические тесты используют подписанные тестовые ответы и не обращаются к провайдерам.

Нужен доступный провайдеру HTTPS-адрес приложения. GitHub Pages исполняет только статический лендинг, PHP и возвраты авторизации там не работают. До готовности MVP Beget не используем. Публичный тестовый сервер или временный защищенный адрес для проверки входа выбираются отдельно; сейчас приложение доступно только локально.

1. Telegram: настроить приложение входа через BotFather согласно официальной инструкции, разрешить адрес сайта и точный URL возврата `https://АДРЕС/auth/telegram/callback`. Полученные client ID и secret сохранить только в локальный/серверный `.env` как TELEGRAM_CLIENT_ID и TELEGRAM_CLIENT_SECRET; TELEGRAM_REDIRECT_URI должен совпадать с зарегистрированным URL.
2. VK ID: создать приложение входа в своем аккаунте, зарегистрировать адрес и точный возврат `https://АДРЕС/auth/vk/callback`. Сохранить VK_CLIENT_ID и VK_REDIRECT_URI в `.env`. Реализован обмен кода с PKCE и device_id; телефон и email не запрашиваются.
3. На выбранном HTTPS-стенде задать APP_URL, APP_ENV=production, APP_DEBUG=false, SESSION_SECURE_COOKIE=true; обеспечить приватный `.env` и корень сайта `application/public`. Не использовать local-access на публичном стенде.
4. Проверить вход обоими способами, приглашение другого человека, явную привязку в разделе «Аккаунт» и повторный вход каждым способом. Совпадение имени не связывает два уже созданных аккаунта. Проверить обычный браузер телефона и браузеры внутри Telegram/VK.

Пароли и секреты в чат и Git не отправлять. Пока настройки пустые, кнопка соответствующего провайдера честно недоступна.

Источники механизма: [Telegram Login](https://core.telegram.org/bots/telegram-login), [официальный VK ID SDK](https://github.com/VKCOM/vkid-web-sdk). Совместимость реальных настроек и адресов подтверждается отдельным проходом, не наличием этих ссылок.

## Проверки и остановка

```powershell
./tools/environment/Test-Application.ps1
Set-Location application
npm.cmd run typecheck
npm.cmd run build
Set-Location ..
./tools/environment/Stop-Application.ps1
./tools/environment/Stop-LocalMySQL.ps1
```

На Windows тесты запускаются предоставленным скриптом через S:, на Linux — `php vendor/phpunit/phpunit/phpunit --configuration phpunit.xml` с отдельной базой asgard_test. GitHub workflow `application.yml` проверяет PHP 8.4 / MySQL 8.4, зависимости, интерфейс и тесты, включая реальные параллельные процессы. Workflow не разворачивает PHP на Pages.

Результаты локальной проверки 24.10.2026: 34 теста, 168 утверждений; типы и сборка проходят. Проверены настоящий MySQL, одновременное вступление и передача владения, ограничения доступа и сессий. Финансовая приемка, нагрузка, восстановление и реальные провайдеры в эти результаты не входят.

В браузере проверены создание/отзыв ссылки и экраны клуба/аккаунта. Адаптивность проверена на временной странице с теми же собранными компонентами в рамках 320 и 390 px (полезная ширина с полосой прокрутки 305 и 375 px); горизонтального переполнения нет. Это проверка компоновки, не замена тестированию на настоящем телефоне. Временные страницы после проверки удалены.
