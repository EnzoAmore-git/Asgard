# Асгард — Product Vision

Основание: Master Prompt 1.0 и финансовые уточнения из [исходной беседы](https://chatgpt.com/share/6ad9ea0f-fcbc-83ed-b1e3-ed7e7bc34ff0). Статус переноса — README.md.

## Назначение
Система управления посещаемостью и совместными финансами небольших спортивных секций и клубов исторической реконструкции. Аудитория — самоуправляемые сообщества, использующие Excel, тетради и переписки. Юридическое лицо необязательно. Приложение не принимает деньги от имени клубов и не является платежным посредником.

Участники записываются; ответственный подтверждает явку; система начисляет абонемент; казначей подтверждает реальные платежи/расходы. Результат — достоверная финансовая картина без ручного пересчета.

Главная цель MVP: полный расчетный период без параллельного Excel.

## Принципы
Автоматизировать вычисления, а не предполагаемые факты. Минимизировать действия/настройки, использовать понятные значения по умолчанию. Отделять обязательства от движения денег. Сохранять проверяемую историю. Обеспечивать независимость клубов. Не требовать установки приложения.

## Платформа и объем
Закрытый пилот для 1–5 независимых клубов, создаваемых оператором вручную. Русский интерфейс. PWA — основная постоянная платформа: браузеры Android, iPhone, планшетов и десктопов. Приглашение → авторизация → работа в браузере; установка на домашний экран опциональна. Mobile First, удобные административные таблицы на десктопе.

MVP: клубы/приглашения, Telegram/VK, совмещаемые полномочия, членство, расписание, запись и фактическая явка, абонементы/освобождения, платежи и накопленные долги, наличные/частичная передача, казна/расходы/возвраты/корректировки/сверка, уведомления, Excel.

Будущее: SaaS, упаковка для Google Play, RuStore, App Store. Мобильные клиенты и Telegram-бот должны использовать общие API и бизнес-правила без переписывания логики. Не реализовывать их заранее.

## За пределами MVP
Без отдельного запроса не добавлять SaaS-подписки, коммерческий биллинг, публичную регистрацию клубов, целевые сборы, выплаты за мероприятия, автоматические банковские переводы, сложные зарплатные ведомости, семейный бюджет, универсальную финансовую CRM, маркетинговые инструменты, продажные воронки, сложные произвольные тарифы, оплачиваемые разовые посещения, нативные приложения, микросервисы без доказанной необходимости.

Не превращать продукт в универсальную бухгалтерию/конструктор процессов. Для новой настройки объяснять, почему недостаточно разумного значения по умолчанию. Точки расширения допустимы, отложенные функции не реализуются.

## Дизайн
Историческая реконструкция, сдержанная скандинавская эстетика. Фон #1A1C23 / #0F172A, текст #E2E8F0, бронза #D4AF37; дополнительные оттенки долгов, оплат, предупреждений. Читаемый гротеск, умеренно декоративные заголовки. Без избытка рун, орнаментов, градиентов и металлических эффектов. Приоритет — интерфейс: крупные зоны нажатия, контраст, очевидные состояния, минимум обязательных полей, понятный русский язык.

Отдельное уточнение для лендинга: по прямому запросу пользователя выполнен более выразительный викингский дизайн с драккаром, северным пейзажем, новым корабельным знаком и крупной антиквой. Приоритет — телефон, включая иллюстрации приложения; тексты для участников клуба должны быть простыми, без айтишных и бухгалтерских терминов. Решения и активы описаны в landing/DESIGN.md. Это направление презентационной страницы не меняет требований к удобству будущего приложения.
