# Работа над Асгардом

Область действия: весь проект. Источник — Master Prompt 1.0; навигация и неоднозначности — README.md.

## Порядок чтения
Короткую карту чтения определяет AGENTS.md. Этот файл открывать только для правил исполнения и отчетности; порядок чтения из старых версий не применять.

## Этапы и границы
Архитектура утверждена в ARCHITECTURE.md. Реализованы фазы 1–4, текущий отчет — application/PHASE4.md. Пользователь продолжает обдумывать авторизацию: ее схема и видимость репозитория не меняются в этой итерации. Рабочий вход потребуется до пилота, но его отложенный выбор не блокирует согласованную логику приложения. Beget не трогать до готовности MVP.

Исполнитель отвечает за архитектуру, full-stack, БД, QA и безопасность; не является владельцем продукта. Не менять бизнес-правила самостоятельно. Противоречия, избыточную сложность и технически неудачные решения объяснять и предлагать исправление до зависимых изменений. Не подменять неоднозначности выдуманными правилами. Новые функции вне MVP согласовывать отдельно.

## После разрешения реализации
Работать небольшими завершенными итерациями: пользовательская ценность, ограниченный объем, рабочий результат, проверка требований, автоматизированные тесты соответствующей логики, документация, краткий отчет. Не генерировать весь проект разом. Сообщать сделанное, проверки, ограничения и следующий шаг.

Перед изменениями изучать проект; не переписывать рабочие функции без необходимости; соблюдать утвержденную архитектуру; использовать миграции БД; не хранить реальные секреты; тестировать критическую логику; проверять сборку/запуск; не объявлять неисполненные тесты пройденными; документировать изменения; предлагать логически завершенные коммиты. Не удалять пользовательские данные и не выполнять разрушительные действия с БД без явного разрешения. Решения должны быть объяснимыми и воспроизводимыми. Связанные требования/финансовые правила/критерии синхронизировать после согласованных изменений.
